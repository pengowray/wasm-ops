Standardised extensions

Finished proposals, folded into the specification. Those that added or changed instructions:

  • Non-trapping float-to-int conversions — 0xFC 0–7
  • Sign-extension operators — 0xC0–0xC4
  • Bulk memory operations — 0xFC 8–11
  • Reference types — 0xD0–0xD2, 0x25, 0x26, 0xFC 12–17
  • Fixed-width SIMD — the 0xFD prefix
  • Relaxed SIMD — 0xFD 256–275
  • Tail call — 0x12, 0x13
  • Typed function references — 0x14, 0x15, 0xD4–0xD6
  • Garbage collection — 0xFB 0–30, and ref.eq at 0xD3
  • Exception handling — 0x08, 0x0A, 0x1F. The earlier try/catch/delegate encoding is still emitted by older toolchains; turn on “Legacy, withdrawn & dormant” to see it
  • Multiple memories and Memory64 — no new opcodes; they widen the immediates existing memory instructions carry
  • Extended constant expressions, Multi-value, Branch hinting — no new opcodes

Active proposals

Tracked at WebAssembly/proposals. Phases run 1 (idea) to 4 (standardising); those that add instructions:

  • Threads — phase 4 — the 0xFE prefix
  • Wide arithmetic — phase 3 — 0xFC 19–22
  • Stack switching — phase 3 — 0xE0–0xE6
  • Relaxed atomics — phase 2
  • Multibyte array access — phase 2 — no new opcodes: it lets the existing load and store instructions address arrays, by adding a type index to their memarg
  • Rounding variants — phase 2
  • Half precision — phase 1 — 0xFC 48–49 and 0xFD 288–335
  • More array constructors — phase 1
  • Memory control — phase 1 — memory.discard and related
  • Flexible vectors — phase 1
  • Shared-everything threads — phase 1
  • Reference-typed strings — phase 1 — 0xFB 128+. Dormant since 2023; no engine implements it

Proposals reaching phase 5 move to finished proposals. Ones that stall are listed as inactive — among them the constant-time extension and call tags, which earlier versions of this page listed as upcoming.
